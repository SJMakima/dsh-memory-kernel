# 外部记忆导入规范（External Import Spec）

**版本**：1.0 · **适用**：任何想把自己的记忆数据导入 dsh-memory-kernel 插件库的外部插件 / bridge / 脚本。

**一句话**：按本规范导出一个 JSON 文件，跑一条命令，完成幂等导入。不需要修改内核代码。

---

## 1. 导入命令

```bash
node scripts/import-external.mjs --file <spec.json> [--dry]
```

- `--file`：规范 JSON 的路径（见 §2）
- `--dry`：只预览（列出将导入的条目），不写库

导入是**幂等**的：每条候选的 `locator` 是幂等键，库里已存在同 locator 的条目直接跳过——**重复执行安全，跑一百遍也只有一个副本**。

## 2. 规范 JSON 格式

```json
{
  "source": "snowluma",
  "domain": "dsh",
  "items": [
    {
      "text": "用户喜欢喝矿泉水",
      "entryType": "fact",
      "topicTags": ["snowluma", "饮品"],
      "observedAt": "2026-10-27T10:00:00Z",
      "triples": [
        { "subject": "用户", "attribute": "偏好", "value": "矿泉水" }
      ],
      "locator": "snowluma:pref:42"
    }
  ]
}
```

### 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `source` | ✅ | 来源标识（如 `snowluma` / `qq-bridge` / `bili`）。进入 `source_ref` 与审计，用于来源追溯和按来源统计 |
| `domain` | ❌ | 目标域，默认 `dsh`。域决定隔离边界（路由/配额/词表），除非有明确隔离诉求，用默认 |
| `items` | ✅ | 候选数组，见下 |

### items[] 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | ✅ | 记忆原文。**一行陈述句，稳定表述**（见 §3 质量要求） |
| `locator` | ✅ | 来源内稳定唯一的幂等键。**不允许空白字符**。内容改写 = 换 locator。**不需要带来源前缀**（导入器自动拼成 `source:locator`），推荐 `类别:编号` 或 `类别:内容短哈希` |
| `entryType` | ❌ | `fact`（默认）/ `pattern` / `boundary` / `skill`。白名单外按 `fact` 处理并提示 |
| `topicTags` | ❌ | 标签数组。**建议首位为来源名**；ID/号码类放这里（会进 FTS 索引，可被检索） |
| `observedAt` | ❌ | ISO 时间。记录于 provenance（条目的 `observed_at` 用导入时刻，回填历史时间暂不支持） |
| `triples` | ❌ | 三元组数组 `{subject, attribute, value}`。**有结构化信息强烈建议提供**——三元组是同键消解、取代链、精确检索的基础；纯 text 条目享受不到这些 |

## 3. 质量要求（导入方自律清单）

1. **一行陈述句**：`text` 是"用户喜欢喝矿泉水"这样的稳定表述，不是聊天记录、不是原文摘抄、不带说话人前缀
2. **关于用户本人，`subject` 一律写 `"用户"`**——内核有别名折叠表兜底，但源头规范能省掉消解成本
3. **`attribute` 用白名单词**：偏好 / 身份 / 位置 / 计划 / 技能 / 边界。同义口语（喜好/口味/爱好）内核会折叠到"偏好"，但规范写法优先
4. **不导入**：会话级暂态（当前话题、进行中的事）、纯闲聊、低价值重复内容——它们会被半衰期淘汰，导入只是浪费配额
5. **不导入他人隐私**：第三方平台的他人数据没有主人的授权语境
6. **稳定优先于新鲜**：拿不准是不是长期事实的，宁可不导

## 4. 幂等与更新语义

- **同 `locator` 重复导入** → 跳过（不覆盖）
- **内容变了** → 你必须**换 locator**（推荐在 locator 里编入内容哈希或版本号），新条目作为新记忆进入，走四分类（与旧条目同键同值会被判 redundant、同键异值会触发 update 取代链——**取代链会自动处理新旧状态**，不需要你做任何清理）
- **删除**：本规范不提供删除。错误导入的条目联系库管理员在真相源 Markdown 中处理（rebuild 即生效）

## 5. 已知边界

- `observedAt` 只进 provenance，条目的 `observed_at` 用导入时刻（历史时间回填需要内核侧支持，暂未提供）
- 导入走完整写入管线（四分类 + 配额），来源方无法绕过质量防线——这是特性不是缺陷
- `--dry` 永远安全，**接入前先用它预览**

## 6. 参考实现

qq-bridge 的导入是本规范的前身：`scripts/import-qq-memory.mjs`（qq 专用解析 + 幂等写入），其 adapter 在 `src/adapters/qq-memory.js`。结构化账本类来源（有字段映射逻辑的）可以仿照它写 adapter 进 `scripts/`；纯声明式来源直接产规范 JSON 用通用导入器即可。
